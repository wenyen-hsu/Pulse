# Security reporting · 安全回報

## English

This policy is for the independent Pulse Pet fork, not upstream Pulse.

- Never attach API keys, cookies, login tokens, keychain contents or unredacted logs to a public issue or pull request.
- If **Report a vulnerability** is available in [this fork's Security tab](https://github.com/wenyen-hsu/Pulse/security), use that private channel.
- If private reporting is unavailable, open a minimal [issue](https://github.com/wenyen-hsu/Pulse/issues/new) asking the maintainer for a private contact channel. Do not include vulnerability details or sensitive attachments until a private channel is agreed.
- Describe the affected version, macOS version and impact privately. Revoke any exposed credentials with the relevant provider.

Private vulnerability reporting is a repository setting; this file does not enable it. There is no promised response or remediation deadline.

## 繁體中文

本政策適用於獨立客製版 Pulse Pet，不是上游 Pulse。

- 請勿在公開 Issue 或 PR 附上 API Key、Cookie、登入 Token、鑰匙圈內容或未遮蔽的紀錄。
- 若[本儲存庫 Security 頁面](https://github.com/wenyen-hsu/Pulse/security)提供 **Report a vulnerability**，請使用該私密管道。
- 若沒有私密回報功能，可建立簡短的 [Issue](https://github.com/wenyen-hsu/Pulse/issues/new)，僅詢問維護者的私密聯絡管道；確認前不要公開漏洞細節或敏感附件。
- 請在私密管道說明受影響版本、macOS 版本與影響；若憑證已外洩，請向服務商撤銷憑證。

私密漏洞回報需在 GitHub 儲存庫設定中啟用，本文件不會自動開啟，也不承諾回覆或修復期限。
